Summary

You asked three questions: what CanonicalContentService is, whether the terminal/dashboard API split is wrong, and whether presenters are the root of the problem. The short answers:

  • CanonicalContentService (engine/queries/content.py) turns a content reference — the string "{event_id}:{field}" — back into full text when a user clicks ⧉copy or ⧉view. The reference is an untyped str, so the set of legal references exists in two hand-maintained copies — eight minting sites and one resolver allow-table — and the copies have drifted. One drift is a live bug: every file edit whose operation finishes with a result mints a reference the resolver answers with a 400.
  • The two API packages are not duplicated. api/terminal is 7 routes for the kitty pane processes; api/dashboard is 44 routes for the browser; their paths, verbs, and services are disjoint. What they share — the guard, the error shape, the SSE vocabulary — already lives in api/common and api/sse.py. Unifying them is a naming and packaging change, not a rescue.
  • Your instinct about presenters is right, but the diagnosis needs one refinement. The problem is not that presenters exist — something must turn an activity into pixels. The problem is that each presenter makes two kinds of decision at once: semantic (what to call this, what state it is in, which text is copyable) and formal (which bytes paint it). The semantic half is duplicated between terminal/mirror/presenter.py and dashboard/render/items/ — ten near-identical decision tables, counted in this document — and the content-reference mess is one of those ten. Fix the boundary and both complaints resolve together.
◆
Key point: The thesis of the TO-BE design: split "what to show" from "how to paint". One function describes an activity as a typed, surface-neutral view; two small renderers turn that view into HTML and into ANSI. The presenters disappear, the duplication disappears, and the content reference becomes a typed value that one module both mints and resolves.

This document supersedes docs/html/content-references.html, which covered the reference half only. Everything here comes from reading the code at today's working tree; the one claim not verified at runtime is marked where it appears.

The concepts

Seven things carry a block of text from the event store to a click. Each is named as the code names it.

Canonical event
The immutable stored fact, identified by a CanonicalEventId. Its payload is one of the typed classes in domain/events.py — MessageCreated, OperationFinished, FileAccessed. Some payload fields hold arbitrarily large text.
Activity
What the fold in engine/projections/activity.py produces: one thing that happened, built from every event about it. An OperationActivity is the start, all progress chunks, and the finish, collapsed into one frozen dataclass with command_text() and output_text() methods (engine/projections/models.py:85). Eleven activity classes exist; this layer is clean and stays.
Content reference
An event id plus a field name, formatted as "{event_id}:{field}" — for example progress-two:operation_output. It has no type; it is a str everywhere it appears, including as a database primary key.
Presenter
The code that turns an activity into what a surface draws. Two exist and neither imports the other: DashboardPresenter (dashboard/render/items/__init__.py:66, a registry dict keyed by activity class) produces DashboardItem; TerminalPresenter (terminal/mirror/presenter.py:258, an isinstance ladder) produces TerminalUpdate.
DashboardItem
dashboard/render/items/item.py:63 — one rendered block for the browser: pre-escaped HTML plus 21 metadata fields, three of which are reference strings. Copied field-for-field into the Pydantic ActivityItem by api/dashboard/mapper/activity.py:18 and shipped over SSE as JSON.
TerminalUpdate
terminal/mirror/blocks.py:58 — replaced and removed blocks of styled lines. TerminalRenderer (terminal/mirror/renderer.py:156) turns them into an ANSI screen; the pane client (client/terminal_pane.py) copies the bytes to the terminal and draws nothing of its own.
Opened view
Terminal-only state: which references the mirror has expanded in place. Stored in the opened_views table, whose primary key is the reference string (repository/impl/sqlite/schema.py:254).

AS-IS: the pipeline

Both surfaces read the same fold through SessionQueries (engine/projections/queries.py). The fork happens immediately after: each surface has its own presenter, its own item model, its own stream route, and its own client.

The stream mechanics differ on purpose and are not the problem. The browser gets a cursor-bearing activity stream plus change-detected application snapshots on one connection (api/dashboard/streams.py:107); the pane gets fully painted screens because the pane client is deliberately a byte-copier — a resize is a reconnect at the new width (api/terminal/streams.py:35). Neither uses a broker; every stream is an async generator polling SQLite through off_loop.

AS-IS: the content reference, stage by stage

A reference is minted on the way out and parsed on the way back in. It is never stored in a canonical payload — it is derived on every read, so changing its shape needs no backfill. Only the opened_views table persists it.

1Foldrecords event id + field name
2Mint8 sites format the string
3Shipitem field, or OSC 8 link
4Clickbrowser fetch, or subprocess
5Resolvesplit the string, guess its meaning

Stage 1: the fold records a loose pair

Every activity that can carry large text gets two unrelated optional fields. Nothing constrains the second to a known set; ten sites in engine/projections/activity.py assign it as a bare literal chosen by the branch they sit in.

Stage 2: eight sites mint the string

The wire format lives in eight places. One is a helper that also applies a size rule; the other seven are inline f-strings. The terminal pair and the dashboard pair for operations are byte-for-byte identical logic, written twice.

The 4096-character rule is a presentation decision — offer copy and view links only when the text is big enough to want them — and it reaches one site of eight. The other seven offer the affordance unconditionally.

Stages 3 and 4: two rides, one constraint

In the browser, the reference sits in node.dataset.contentReference; a delegated click listener fetches /api/content/{ref} and either writes the clipboard or inserts a view block (dashboard/static/app.05-session.js:473-537). For file items the client appends ?view=diff|source&path=…, re-deriving from dataset.summaryKind a choice the server could read off FileAccessed.path itself.

In the terminal, the same reference becomes a URI inside an OSC 8 hyperlink under a custom scheme — baqylau-content:// to copy, baqylau-view:// to expand (terminal/mirror/renderer.py:43). A click launches client/terminal_content.py or client/terminal_view.py with the URI as argv[1]. This is the one hard constraint on any redesign: the reference must survive as a single URI-safe token, because a hyperlink cannot carry a request body.

Stage 5: the resolver rediscovers what the minter meant

The whole of CanonicalContentService is one method. It splits the string with rpartition, loads the event, and then guesses: three field names are virtual and trigger a re-fold of the operation; everything else is checked against a hand-maintained allow-table keyed by payload type.

The rpartition, the isinstance guard, the allow-table, and the getattr are not four separate messes. They are what a resolver must do when the token it receives carries no type: rediscover, at runtime, what the minter meant. The vocabulary — which addresses exist — is written down nowhere, so it exists twice, and the two copies have drifted in both directions:

  • The allow-table's OperationInputProvided: {"content"} row is dead — no presenter ever mints a reference to that payload.
  • The fold mints an address the table refuses. That is the live bug.

The confirmed bug

When a file-editing operation finishes with a result, the fold moves the file activity's content pointer to the OperationFinished event and names the field "result":

dashboard/render/items/files.py:75 then mints "{finish_event_id}:result". In the resolver, "result" is not one of the three virtual names, and the allow-table has no row for OperationFinished — its "result" row belongs to ActorAssignmentFinished, a different payload. The lookup yields an empty set and UnknownReference is raised, which the API layer answers as a 400. The user sees the file block's ⧉view link, clicks it, and gets a view failed toast. The same untyped field misfires a second way in the terminal: terminal/mirror/presenter.py:289 branches on content_field == "unified_diff" versus == "content", so "result" silently falls through both arms.

What the packages share already lives in shared modules: the control_plane() guard on every POST (api/guard.py:38), the one error body (api/app.py:58), and the SSE vocabulary (api/sse.py). Both follow the same idiom — URL-as-gesture, verdicts instead of errors — as convergent design, not copied code. Three genuine findings, none structural:

  • api/common/content.py:10 imports the dashboard's unified_diff_html/source_html to serve the terminal's click-through. It is the only place the two display stacks touch, and it means one expanded file exists in three renderings.
  • POST /api/sessions/{id}/controls/open-rewind (api/dashboard/controls.py:121) has no caller anywhere — the browser uses only apply-rewind. Wired but unreachable.
  • The client-side split is total: terminal/ and bin/ make no HTTP calls (the adapter spawns client/terminal_pane.py); the browser calls every dashboard route through two funnels, postJSON and sessionControl.

So "two APIs" is a packaging smell, not an architecture flaw: the names say who asks when route names should say what is asked for. The TO-BE section proposes the rename. The load-bearing problem is one layer down.

The root cause, named

The projection layer stops at the right place: eleven typed activity classes, pure, well-named. But the next layer up answers two questions at once:

  1. What should this activity show? A label, a state, a duration, chips, which text is large enough to fetch on demand, whether the body is a diff or plain text. These answers are the same for every surface.
  2. What bytes paint it? Escaped HTML in a JSON field, or SGR sequences and OSC 8 links. These answers are different per surface, and mechanical.

Because no type holds the answers to question 1, each presenter answers both questions inline, and every question-1 answer is written twice. The content reference is the sharpest instance: "which piece of text can be fetched later" is a question-1 answer, spelled as an f-string at eight question-2 sites, and re-guessed by a resolver that was never told the vocabulary. DashboardItem shows the same confusion from the other side: 22 fields mixing identity (item_id, turn_id), semantics (summary_kind, state, three reference strings), and form (html) in one bag.

TO-BE: one description, two renderers

Move the boundary up one layer. Between the projections and the surfaces, add a single surface-neutral description of each activity, and demote both presenters to renderers that hold no opinions.

The reference becomes a value

A new domain/references.py writes the vocabulary down once, as a closed enum of what text you want — not payload field names, because content means five different things on five payloads and operation_output corresponds to no field at all (it is folded from progress chunks).

Consequences, followed out loud:

  • The fold's loose pair content_event_id/content_field becomes one field, content_ref: ContentRef | None. The ten bare-literal assignments in activity.py become constructor calls the type checker reads. The file-edit bug becomes unrepresentable: "result" is not a slot, so the misassignment cannot compile past mypy.
  • The eight f-string mint sites become one: ref.token().
  • The resolver becomes an exhaustive match ref.slot with assert_never, so adding a slot without a reader fails the build. The allow-table, the rpartition, the isinstance guard, and the getattr all disappear. CanonicalContentService is renamed to what it is: ContentResolver, method text(ref: ContentRef) -> str.
  • FILE_SOURCE and FILE_DIFF being distinct slots deletes the ?view= and ?path= query parameters — the server already knows the path from FileAccessed.path, and the slot says which renderer to use. The browser stops re-deriving that choice from dataset.summaryKind.
  • The opened_views primary key stores ref.token(). Rows are ephemeral UI state; the migration is "drop and recreate", not a backfill.

The description becomes a type

One module — a new presentation/ package, or engine/describe/ — holds every question-1 answer. Its output is small and closed:

describe(activity) -> ItemView subsumes both presenters' semantic halves: the file verb table, the attention text, the labels, the 4096-character rule (applied once, for every surface), and all reference minting. The renderers then hold only form:

  • render_html(view) -> DashboardItem — escaping, markdown, CSS hooks. DashboardItem shrinks to identity + html + plain_text; the semantic fields ride on the view.
  • render_ansi(view, width) -> TerminalUpdate — SGR styling, OSC 8 links, line layout. The palette is keyed by semantic role in one table per surface, so "updated is yellow" is stated once each, against the same role name.

Duration, token-count, and cost formatting move next to the view as shared helpers; the JavaScript copies remain (the browser formats live tickers), but they become the only acknowledged second copy, and the scoreboard/JS drift stops growing.

The API becomes one package, named by resource

Dissolve api/dashboard, api/terminal, and api/common into one api/ package of routers named for what they serve, mounted by composition exactly as today's build_web_application already does:

api/
├── sessions.py      # reads + the two session streams
├── controls.py      # launch + gestures (drop open-rewind)
├── content.py       # GET /api/content/{token}, ContentRef.parse at the boundary
├── panes.py         # kitty pane commands + the ANSI frame stream
├── views.py         # the expansion toggle
├── application.py   # preferences, drafts, presence, uploads
└── ingest.py        # hooks, telemetry, health

No route merges and no client changes; the pane stream keeps shipping painted ANSI because the byte-copying client is a good design. "The terminal API" stops existing as a concept; the pane routes are one resource among eight, and a future surface composes the routers it needs. This is deliberately the smallest part of the redesign.

What gets deleted

  • engine/queries/content.py as written: the allow-table, the virtual field names, the getattr.
  • The semantic halves of terminal/mirror/presenter.py and all five dashboard/render/items/ presenter modules — roughly the ten rows of Table 3.
  • content_field: str on two activity classes, and the ten literal assignments feeding it.
  • The ?view=/?path= parameters on the content route, and the browser code that computes them.
  • The dead OperationInputProvided allow-table row and the dead open-rewind route.

Rejected alternatives

Share helpers between the two presenters

The cheap fix: extract the file-verb table, the attention text, the durations into common functions both presenters call. It removes today's copies but keeps the boundary that produced them — the next feature adds a decision to one presenter and forgets the other, exactly as happened eight times already.

Move the boundary

One describe() means a forgotten surface is impossible: a renderer that ignores a view field is visible in one diff, and mypy's exhaustiveness checks cover the closed unions.

Also considered and dropped:

  • Render client-side in the pane. Making the pane client interpret a JSON stream would unify the wire format, but the client is a Python process whose whole value is having no logic — resize as reconnect, no state, no version skew. It would also just move the ANSI renderer across a process boundary, not delete it.
  • One merged stream endpoint for both clients. The browser needs cursors and application snapshots; the pane needs painted frames at a width. Forcing one shape onto both adds a discriminator field and two code paths inside one route — the same fork, hidden.
  • Path-segment references (/api/content/operation-output/evt-7f3a) instead of a token. Cleaner HTTP, but the reference must still exist as one string for OSC 8 URIs and the opened_views key, so the token form survives anyway; two spellings of one value is the current disease.
