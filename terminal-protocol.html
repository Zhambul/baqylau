1. Where the protocol sits in the architecture

The layering rule says shared code (domain, contracts, runtime, app, core, dashboard, frontends, terminal) carries no concrete vocabulary; concrete adapters live one-per-implementation. For harnesses this holds and is enforced. For terminals the intended shape is the same:

consumers (app/, dashboard/, plugins/)
        │  should speak only…
        ▼
contracts/terminal.py         ← neutral protocols + value types (imports: domain only)
        ▲  implemented by…
        │
app/session_terminal.py       ← ApplicationTerminal, the ONE adapter
        │  which delegates to…
        ▼
frontends/  (base.py = inert "none" frontend, kitty.py = the real one)

The actual shape has a second edge the diagram hides: the adapter (plus two thin self-identification clients, §4.4) talks to the Frontend duck-type in frontends/base.py directly. That interface is broader than the contract, undocumented in contracts/, and shaped by kitty's remote-control verbs. Everything in §4 follows from that. Note the duck-type's own slice-consumer comments name modules from the pre-rewrite system (core/hostpane.py, plugins/*/tabstatus.py, plugins/*/split.py) that no longer exist — the live consumer map is §9, and it shows the funnel actually holds: the dashboard HTTP layer imports none of this.

2. The contract — contracts/terminal.py, piece by piece

2.1 Tags and value types

Three tag constants name the panes baqylau owns. They read as neutral strings, but in practice they are kitty user-var names (applied with set-user-vars, matched with var: match expressions) — a mechanism with no direct analogue in iTerm2 or ghostty:

# contracts/terminal.py:11
SESSION_WINDOW_TAG  = "baqylau_session"     # the harness's own window
ACTIVITY_PANE_TAG   = "baqylau_activity"    # the mirror pane
SCOREBOARD_PANE_TAG = "baqylau_scoreboard"  # the 5-row scorebar

The value types are genuinely neutral — validated colours and result records:

2.2 The six protocol roles

SessionTerminal

Session ⇄ window resolution and tab spawning. Used by services that need "where is this session on screen".

class SessionTerminal(Protocol):
    def window_for_session(self, session_id: SessionId) -> str | None: ...
    def current_window(self) -> str | None: ...
    def hosting_session(self, excluding_session_id: SessionId) -> SessionId | None: ...
    def open_tab(self, request: TabRequest) -> TabResult: ...

SessionPaneControl

The mirror + scoreboard pane lifecycle, as one atomic gesture per session.

class SessionPaneControl(Protocol):
    def open_session_panes(self, request: SessionPaneRequest) -> TerminalResult: ...
    def close_session_panes(self, session_id: SessionId) -> TerminalResult: ...

SessionTabControl

Tab colouring keyed by session, not by window — the caller never sees a window id.

class SessionTabControl(Protocol):
    def paint_session_tab(self, session_id: SessionId,
                          appearance: TabAppearance) -> TerminalResult: ...
    def clear_session_tab(self, session_id: SessionId) -> TerminalResult: ...

TerminalScreen

Read-only capture of what a window shows. ansi=True keeps SGR escapes (the ghost-suggestion probe needs the faint-text formatting).

class TerminalScreen(Protocol):
    def read_screen(self, window_id: str, ansi: bool = False) -> ScreenText | None: ...

TerminalControl(TerminalScreen)

The write half of the web control plane: typing into, keying into, titling, and closing windows.

@dataclass(frozen=True)
class TextSubmission:
    text: str
    mode: Literal["type", "paste"]        # paste = atomic bracketed paste; a TUI
                                          # mid-state-change drops leading typed bytes

class TerminalControl(TerminalScreen, Protocol):
    def window_for_session(self, session_id: SessionId) -> str | None: ...
    def submit_text(self, window_id: str, submission: TextSubmission) -> TerminalResult: ...
    def send_key(self, window_id: str, key: str) -> TerminalResult: ...
    def close_tab(self, window_id: str) -> TerminalResult: ...
    def set_tab_title(self, window_id: str, title: str) -> TerminalResult: ...
    def open_tab(self, request: TabRequest) -> TabResult: ...

TerminalFrontend(TerminalControl)

The widest role — what a full frontend is supposed to offer. Note it is much narrower than what frontends actually offer (§4.1).

class TerminalFrontend(TerminalControl, Protocol):
    def usable(self) -> bool: ...
    def current_window(self) -> str | None: ...
    def window_for_session(self, session_id: SessionId) -> str | None: ...
    def tag_window(self, window_id: str, tags: Mapping[str, str]) -> TerminalResult: ...
    def set_tab_color(self, window_id: str, color: RGB) -> TerminalResult: ...
    def clear_tab_color(self, window_id: str) -> TerminalResult: ...
    def open_pane(self, request: PaneRequest) -> PaneResult: ...
    def close_pane(self, pane_id: str) -> TerminalResult: ...
    def resize_pane(self, pane_id: str, request: ResizeRequest) -> TerminalResult: ...

3. The one implementation: ApplicationTerminal

app/session_terminal.py implements SessionTerminal + SessionPaneControl + SessionTabControl + TerminalControl by resolving the installed frontend per call and translating the contract's typed requests into Frontend calls:

class ApplicationTerminal(SessionTerminal, SessionPaneControl,
                          SessionTabControl, TerminalControl):
    def _frontend(self):
        return frontends.get(resolve=True)   # ← the escape hatch (§4)

    def submit_text(self, window_id, submission):
        frontend = self._frontend()
        sender = frontend.paste_text if submission.mode == "paste" else frontend.send_text
        succeeded = bool(sender(window_id, submission.text))
        return TerminalResult(succeeded, None if succeeded else "terminal input failed")

Where the translation is faithful — colours, text, tabs — the contract works as designed. The problem is the methods where no contract vocabulary exists, so the adapter (a shared-layer app/ module) speaks the frontend's raw dialect. That is the next section.

4. What the contract does NOT cover

4.1 STRUCTURAL The second, contract-less interface: frontends/base.py

frontends/base.py defines class Frontend — a single duck-typed class where every method is an inert no-op and kitty overrides what it supports. It is the interface consumers actually program against, and it is far broader than TerminalFrontend. These Frontend methods have no counterpart anywhere in contracts/terminal.py:

So the honest picture is: contracts/terminal.py covers roughly the simple write half of terminal interaction (colour, type, key, title, tab), while enumeration, tagging, split choreography, geometry, scrolling, focus, and presence — most of what makes the pane system work — live only in the frontend duck-type.

4.2 STRUCTURAL Kitty match grammar assembled in app/

This is the sharpest single leak. ApplicationTerminal.open_session_panes — a shared-layer method implementing a contract role — builds raw kitty --match expressions as f-strings and drives the kitty launch choreography step by step:

# app/session_terminal.py:154 — open_session_panes (abridged)
results = [frontend.set_user_vars(anchor_window_id,          # kitty user-vars
                                  {SESSION_WINDOW_TAG: session_id})]
frontend.goto_splits_layout(anchor_window_id)                # kitty goto-layout splits

if frontend.find_window(ACTIVITY_PANE_TAG, session_id) is None:
    results.append(frontend.launch_pane(
        [sys.executable, ".../terminal_process.py", session_id],
        "vsplit",
        bias=request.activity_width_percent,                 # kitty --bias
        next_to=f"id:{anchor_window_id}",                    # ← kitty match grammar
        in_tab_of=anchor_window_id,                          # ← exists only because kitty's
        var={ACTIVITY_PANE_TAG: session_id},                 #    next_to can't cross tabs
        title="◧ cmd mirror",
    ))

if frontend.find_window(SCOREBOARD_PANE_TAG, session_id) is None:
    results.append(frontend.launch_pane(
        [...scoreboard_process.py...],
        "hsplit",
        bias=5,
        next_to=f"var:{ACTIVITY_PANE_TAG}={session_id}",     # ← kitty match grammar again
        in_tab_of=anchor_window_id,
        var={SCOREBOARD_PANE_TAG: session_id},
        title="▪ session",
    ))
results.append(frontend.focus_first_pane(anchor_window_id))

Why this is a protocol failure, not just style. The strings id:<win> and var:name=value are kitty's match-expression micro-language. A ghostty or tmux frontend cannot interpret them; it would have to parse kitty grammar back apart to recover the caller's intent ("anchor next to this window" / "next to the pane tagged X"). The intent is being destroyed at the layer boundary and re-encoded in kitty's dialect — the exact thing "never re-encode a shared fact" forbids. The fix shape: launch_pane should accept a structured anchor (e.g. next_to_window_id=… or next_to_tag=(name, value)) and each frontend renders its own match syntax.

The same method also hand-rolls kitty-specific settle behaviour — retrying resize_pane until the scoreboard reports 5 lines, sleeping 80 ms between attempts (_set_scoreboard_height, app/session_terminal.py:201) — timing tuned to kitty's async resize, living in app/.

And _tab_windows (app/session_terminal.py:49) walks the raw ls() tree, depending on kitty's exact JSON shape (tabs, windows, is_focused, is_active, user_vars) from inside app/:

for operating_system_window in terminal_state:
    for tab in operating_system_window.get("tabs", ()):
        windows = tuple(tab.get("windows", ()))
        ...
    if not operating_system_window.get("is_focused"): continue
    ...
    if tab.get("is_active"): ...

4.3 STRUCTURAL Kitty-shaped assumptions inside the contract itself

Even the clean file encodes kitty's model, just without the word:

  • Stable, first-class window ids. window_id: str / pane_id: str assume every pane has a durable id you can query, match, and store. kitty has these; a generic emulator has at best a tty. The dashboard persists them and the wrapper anchors panes to them.
  • The anchor + bias split model. SessionPaneRequest(anchor_window_id, activity_width_percent) is kitty's launch --location=vsplit --bias=N reified as a dataclass. A tmux frontend thinks in split-window -p; an AppleScript-driven terminal can't express it at all.
  • Tags = user-vars. The three *_TAG constants only work because kitty lets you attach arbitrary key/values to windows and match on them. The contract offers tag_window() but no portable way to find by tag — that lives only in Frontend.find_window.
  • send_key assumes key-event injection. The Frontend.send_key docstring is explicit: encoded for the program's keyboard mode, because "a TUI in the kitty keyboard protocol never sees a bare \x1b as Escape". The contract method inherits that requirement silently.

4.4 STRUCTURAL Direct frontends imports that bypass the contract

ApplicationTerminal is at least trying to be the adapter. These callers skip even that:

# app/hook_client.py:43 — the hook needs its own window id for evidence
import frontends
window_id = frontends.current_window_id()

# app/terminal_panes.py:25 — the keybinding handler resolving "which pane am I in"
import frontends
win = frontends.current_window_id()

And that is the whole list — exactly three modules import frontends raw, and the two above only for current_window_id(), which is justified: a hook subprocess and a keymap client run inside the kitty window and are the only things that can observe their own window id. (An earlier draft of this section listed core/hostpane.py, plugins/*/tabstatus.py, plugins/*/split.py, dashboard/server.py as duck-type consumers — those come from frontends/base.py's own slice comments, which describe the pre-rewrite system; none of those files exist in this tree. The stale comments are themselves a small leak: the interface documents consumers that died.)

The daemon serves a neutral field, and the SPA renames it into kitty vocabulary at the door, then reads that name in seven files:

4.6 INCIDENTAL Kitty as the hard-wired default frontend

# frontends/__init__.py:20
name = os.environ.get("BAQYLAU_FRONTEND", "kitty")   # kitty unless told otherwise

Not detection — a default. Outside kitty with the env var unset, every consumer gets the kitty frontend whose available() returns False, and degrades through the inert paths. Harmless today, but it means "no terminal" and "kitty not reachable" are indistinguishable, and adding a second real frontend requires every user to set the variable.

Also incidental: ~12 shared-layer Python files mention kitty in comments/docstrings only (app/terminal_panes.py:3, app/pane_commands.py:4, dashboard/clipboard.py, dashboard/ansi.py:123, dashboard/notify/presence.py, plugins/claude_code/{suggestion,transcript,tui,askdialog,rewindmenu}.py…), and the build config uses a kitty pytest marker for the opt-in real-terminal smoke suite.

5. Why no test catches this

The harness side has a purity gate; the terminal side has none:

# tests/test_canonical_architecture.py:148
def test_canonical_shared_code_contains_no_concrete_harness_vocabulary():
    # scans app/ contracts/ core/ dashboard/ domain/ frontends/ runtime/ terminal/
    forbidden = ("claude", "codex", "anthropic", "openai", "rollout", "transcript")
    # … "kitty" and "kitten" are NOT in this tuple

Two structural reasons the symmetric test never appeared:

  1. The scan list includes frontends/ — correct for harness words, but a terminal-purity scan must exclude frontends/kitty.py (that's where kitty is supposed to live). The test needs its own directory list, not a word added to the existing tuple.
  2. The leaks aren't (mostly) the word "kitty". next_to=f"id:{…}" contains no forbidden string. A vocabulary scan catches the JS field and the comments; the structural leaks need the interface itself to move (§7).

What is pinned: tests/test_l0_frontends_contract.py guarantees every Frontend method has an inert default and kitty adds no public API beyond the duck-type — substitutability, but of the wrong, wider interface.

7. What closing the gap would look like

  1. Structured anchors instead of match strings. Change launch_pane to take next_to_window_id: str | None and next_to_tag: tuple[str, str] | None; each frontend renders its own match syntax (kitty: id:… / var:…=…). Delete both f-strings from app/session_terminal.py. This alone removes the worst leak without moving any code.
  2. Promote the used slices into contracts/terminal.py. Enumeration (windows() yielding a typed WindowInfo(id, tags, columns, lines, tab_focused) instead of raw ls() dicts), presence (app_focused/tab_focused), scroll, geometry, and tag-lookup (window_for_tag(name, value)). Then _tab_windows stops walking kitty JSON.
  3. Kill the bypasses. app/hook_client.py and app/terminal_panes.py get current_window() from the adapter; the pane choreography moves behind open_session_panes so core/hostpane.py and the split plugin speak contract types.
  4. Rename kitty_window_id → terminal_window_id in the SPA (one construction site, ~12 readers, no server change).
  5. Add the missing purity test: forbid kitty/kitten in app/ contracts/ core/ dashboard/ domain/ runtime/ terminal/ plugins/ and in the JS — everything except frontends/ — mirroring the harness test's shape. It won't catch the structural leaks, but it stops regrowth once steps 1–3 land.
  6. Detect instead of defaulting: frontends/__init__.py picks the frontend whose available() is true, keeping BAQYLAU_FRONTEND as an override.

8. The refactor — frontends/ removed, one TerminalPlugin, complete

Today the terminal story is split across three top-level packages: the contract in contracts/, the presenters in terminal/, and the implementations in frontends/ — with the adapter stranded in app/. The refactor: delete the frontends/ package entirely (the Frontend duck-type and kitty.py both), and replace the six overlapping contract roles with one composition class, TerminalPlugin, mirroring HarnessPlugin — five narrow sub-protocols (tabs, panes, metadata, input, viewport) composed as typed fields, with all models in a terminal/models/ package. One terminal/ package owns the whole terminal concern — contract at its root, concrete terminals under terminal/impl/<name>/, and the presenter grab-bag reorganised into meaningful blocks (§8.4).

8.1 The unlock: the session already knows its window

The Session read-model carries terminal facts as live columns, refreshed from the envelope of every hook-borne fact — because a resumed session shows up in a new window with a new process:

# contracts/harness.py:128 (docstring: "the two LIVE columns … are kept
# current from the envelope of every later hook-borne fact")
@dataclass(frozen=True)
class Session:
    session_id: SessionId
    lead_actor_id: ActorId
    harness_session_id: str
    source_reference: str
    working_directory: str | None
    terminal_window_id: str | None = None     # ← evidence, hook-envelope fresh
    harness_process_id: int | None = None     # ← evidence
    plugin: HarnessPlugin | None = ...

# runtime/sessions.py:40 — the upsert keeps it current:
#   "terminal_window_id = excluded.terminal_window_id"

The hook observes its own window (app/hook_client.py:43, the one legitimate raw read) and ships it in every delivery. So session → window resolution is an evidence lookup, not a terminal interrogation: the old window_for_session(session_id) — which walks kitty's ls() tree matching the SESSION_WINDOW_TAG user-var — re-derives a fact the session row already holds. Consequences:

  • The session-aware roles (SessionTerminal, SessionPaneControl, SessionTabControl) leave the contract. Services resolve session.terminal_window_id from the store, verify liveness against windows() (the row can outlive the window), and call the terminal by window id.
  • terminal/contract.py drops its domain.ids.SessionId import entirely — the terminal abstraction no longer knows sessions exist. It is a pure driver keyed on window ids.
  • The tags stay, but demoted to what they really are: generic window metadata. SESSION_WINDOW_TAG becomes a liveness cross-check; the two pane tags still mark the daemon-created mirror/scoreboard (those are not evidence-born, so the terminal must be able to find them after a daemon restart).

8.2 The whole contract — TerminalPlugin + five sub-protocols, every method

One composition class, mirroring HarnessPlugin (contracts/harness.py:700 — a frozen dataclass with one typed field per sub-protocol). A terminal is a plugin: five narrow protocols for tabs, panes, metadata, input, and viewport. Models live in terminal/models/, grouped per concern, terminal-agnostic, and uniformly named <Noun><Verb>Request / <Noun><Verb>Response — every operation is one request in, one response out (each request carries its target window_id; no bare-argument writes), the same shape discipline as the new api/models.py layer:

The protocols — terminal/contract.py, complete. Uniform shape: one request in, one response out. Every write is best-effort and silent: a failure is a failure-shaped response, never an exception; the caller audits.

class TerminalTabs(Protocol):
    def open_tab(self, request: TabOpenRequest) -> TabOpenResponse:
        """Must NOT steal OS focus when the terminal app is backgrounded."""
    def close_tab(self, request: TabCloseRequest) -> TabCloseResponse: ...
    def rename_tab(self, request: TabRenameRequest) -> TabRenameResponse: ...
    def set_tab_color(self, request: TabColorSetRequest) -> TabColorSetResponse: ...
    def clear_tab_color(self, request: TabColorClearRequest) -> TabColorClearResponse: ...


class TerminalPanes(Protocol):
    def open_pane(self, request: PaneOpenRequest) -> PaneOpenResponse:
        """Split next to the anchor. The impl arranges whatever layout it
        needs (kitty: goto-layout splits) — not the caller's concern."""
    def close_pane(self, request: PaneCloseRequest) -> PaneCloseResponse: ...
    def resize_pane(self, request: PaneResizeRequest) -> PaneResizeResponse: ...
    def focus_window(self, request: WindowFocusRequest) -> WindowFocusResponse:
        """With WindowInfo.is_first_in_tab this subsumes focus_first_pane."""


class TerminalMetadata(Protocol):
    def windows(self) -> tuple[WindowInfo, ...]:
        """Every window the terminal reports. () on failure. The daemon's ONE
        state read — everything else here is a write. Subsumes ls /
        iter_windows / find_window / window_for_session / tab_focused /
        split_geometry: liveness (a Session.terminal_window_id can outlive
        its window), pane rediscovery (toggle idempotence), tab grouping
        (which session owns the keypress's tab), host detection
        (is_first_in_tab), and the width-percent arithmetic."""
    def tag_window(self, request: WindowTagRequest) -> WindowTagResponse:
        """Store 'this window serves session X' IN the window, so the mapping
        has exactly the window's lifetime — never stale, survives daemon
        restarts. The write half of windows()' tag read."""
    def current_window_id(self) -> str | None:
        """This process's own window (from the terminal's env), else None.
        The ORIGIN of all window evidence: the hook client ships it as the
        X-Baqylau-Terminal-Window header, which is where
        Session.terminal_window_id comes from."""


class TerminalInput(Protocol):
    def submit_text(self, request: TextSubmitRequest) -> TextSubmitResponse:
        """Deliver text + Enter (subsumes send_text AND paste_text)."""
    def send_key(self, request: KeySendRequest) -> KeySendResponse:
        """Encoded for the program's current keyboard mode."""


class TerminalViewport(Protocol):
    def read_screen(self, request: ScreenReadRequest) -> ScreenReadResponse: ...
    def scroll(self, request: ViewportScrollRequest) -> ViewportScrollResponse:
        """The fast raw-socket path is the impl's own optimisation
        (subsumes scroll_window / scroll_window_fast / scroll_window_end)."""


@dataclass(frozen=True)
class TerminalPlugin:
    """One terminal, composed — the exact shape of HarnessPlugin."""
    name: str
    tabs: TerminalTabs
    panes: TerminalPanes
    metadata: TerminalMetadata
    input: TerminalInput
    viewport: TerminalViewport

The two reads without a request object are deliberate: windows() and current_window_id() take no parameters, so a request dataclass would be an empty envelope; WindowInfo, RGB, TabAppearance, and PaneAnchor are value objects/entities, not messages, so they carry no Request/Response suffix. The generic TerminalResult is gone — every operation owns its response type, so adding an operation-specific field later (as TabOpenResponse.window_id already shows) never disturbs its neighbours.

No usable(), no app_focused(), no pane_geometry(), no launch_environment():

  • usable() is gone because usability is a resolution concern, not a per-call one: terminal.impl.resolve() -> TerminalPlugin | None returns a plugin only when its control channel is reachable and its client binary resolves. Every TerminalPlugin a consumer ever holds is usable by construction; "no terminal" is None at the injection point (bootstrap), handled once. The old per-call checks (open_session_panes, open_tab) existed only because frontends.get() could hand back a dead frontend.
  • app_focused() is gone — its only documented consumer (presence routing via mark_terminal(), §9.5) has no production caller. Dead vocabulary; reintroduce with the presence feature, on TerminalMetadata, if it ever lands.
  • pane_geometry() is gone — it existed for one gesture (set the activity pane to N% of its row: percent → column delta needs the pane's columns and the row total; exclude_tag kept the scoreboard, which lives inside the activity split group, from double-counting the total). All of that is arithmetic over windows(): the adapter finds the host and activity panes of the tab by tag and computes row_total = host.columns + activity.columns. One derived read replaced by the general one.
  • launch_environment() is gone — its predecessor export_env() has zero production callers (definition + one stale comment; its consumer, tabstatus, died in the rewrite). Nothing needs it: the pane processes are launched by the terminal and inherit its env; the hook processes are spawned by the CLI inside the window and inherit likewise. Same fate as app_focused — dead vocabulary does not get a seat in the new contract.

8.5 What the move buys, concretely

  • One import boundary to police. The purity test from §7.5 becomes trivial: forbid kitty/kitten everywhere except terminal/impl/kitty/, and forbid import terminal.impl outside terminal/ itself (only terminal/impl/__init__.py resolves an impl; everyone else takes the contract). Today that test can't even be written cleanly because frontends/ sits inside the harness-purity scan list.
  • The two-interface problem dissolves. class Frontend is deleted; the null and kitty plugins both implement the same five sub-protocols, and test_l0_frontends_contract.py is repointed to assert exactly that (every sub-protocol method present, no public API beyond them). "The contract" and "what consumers actually call" are the same file for the first time — and the stale slice comments naming dead pre-rewrite consumers (§4.4) die with frontends/base.py.
  • A second terminal is a directory. terminal/impl/ghostty/ or terminal/impl/tmux/ implements terminal/contract.py, renders its own match/anchor syntax in its own match.py-equivalent, and registers with the detector — no shared-layer edits.

Three migration constraints. (1) terminal/ must NOT import app/ after the move (the adapter moved out of app, and an app → terminal.adapter → app cycle would form) — the adapter takes the session store as a constructor dependency instead of importing it. (2) tests/test_canonical_architecture.py's scan lists reference frontends/ (harness-purity list, line ~148) and must swap to terminal/-minus-impl/ in the same commit, which is also the moment to add the kitty/kitten purity test (§7.5). (3) The daemon does not hot-reload: land the rename, restart with bin/baqylau-dashboard.py stop && … start, and hard-reload the browser.
