1. How it works today

The whole layer is hand-rolled on the Python standard library — http.server.ThreadingHTTPServer plus BaseHTTPRequestHandler. There is no framework, no router, no request/response model objects: routing is if-chains over split path segments, request bodies are hand-validated dicts, and responses are hand-assembled dicts or generic dataclass serialization.

It lives in dashboard/http/, but it is not a dashboard-only concern. It is the daemon's single door: the browser SPA, the harness hooks (Claude Code and Codex), the kitty mirror pane, the kitty scoreboard pane, the pane keybinding handler, and the two click-to-open protocol handlers all speak to the same server. This misplacement is one of the three motivations for the refactor (§10).

The handler is a mixin stack

    protocol_version = "HTTP/1.1"

Dispatch rides Python's MRO: do_GET (defined in _GetMixin) calls self.route(...), which resolves to _CanonicalMixin.route first; it handles /api/… and falls through via super().route(...) to the static/probe router. do_POST works the same way through route_post. So the routing table is implicit in the inheritance order — you cannot read the URL space in any one place.

Server lifecycle — the daemon builds the graph exactly once

serve() (dashboard/http/handler.py:70) is the one process that builds the application graph:

  1. Acquires the pid-lock (paths.DASHBOARD_LOCK_DATABASE, key dashboard); a denied claim is audited and exits 1.
  2. Opens an audited stream (kind dashboard) covering the whole run — uptime and exit path are queryable.
  3. Binds 127.0.0.1:8377 (BAQYLAU_DASHBOARD_PORT overrides the port; the bind address is never configurable). Port busy → audited, exit 1.
  4. Builds the graph via app.bootstrap.build_default_application() and hangs it on the server object as httpd.canonical_application — every handler thread reaches it through self.server.canonical_application.
  5. Starts three daemon threads: the interpreter (application.interpreter.run, the one read-and-interpret loop, 0.25 s tick), the usage poller (application.usage_state.run), and the notifier.
  6. Prunes composer-attachment uploads older than 7 days.
  7. serve_forever(poll_interval=0.5); SIGTERM raises SystemExit; shutdown joins the threads and ends the audit stream (stopped / crash).

The CLI (dashboard/cli.py) wraps this: start spawns serve detached, stop SIGTERMs the lock-holder pid, status reads the lock. The CLI itself never speaks HTTP.

Concurrency model: ThreadingHTTPServer with daemon_threads = True and request_queue_size = 128 (the stdlib default backlog of 5 caused kernel resets under the cloudflared tunnel's ~16-connection refresh bursts — the "502 / half-loaded page" failure). Each request gets a thread; each SSE connection occupies its thread for its whole life, polling shared state every 0.25 s. BrokenPipeError/ConnectionResetError are swallowed at every level (a departed client is not an error). Hook recording happens on these HTTP threads, deliberately decoupled from the interpreter tick: a wedged tick cannot stop hook capture.

2. Plumbing: responses, SSE, the POST guard, static files

Response path

  • _send(code, body, ctype, cache) — sets Vary: Accept-Encoding always; gzips when the body is ≥ 1024 bytes (GZIP_MIN) and the client accepts it (honouring an explicit gzip;q=0 refusal); Cache-Control defaults to no-store (only versioned statics override it). A write to a departed client is swallowed.
  • _json(obj, code) — json.dumps(obj, default=str) through _send. Note default=str: anything non-JSON left in the object is silently stringified.
  • SSE — _sse_start() sends 200 + text/event-stream + no-store and leaves the response open; _sse(event, obj) writes one event:/data: frame and returns False when the client is gone (ending the loop); _sse_beat() writes the comment : beat. SSE never passes through _send, so streams are never gzipped or buffered.

The control-plane POST guard

Every POST goes through _post_guard (parsed-JSON variant) or _post_guard_bytes (exact-bytes variant, used only by the hook endpoint). It is the browser-vector defense, checked in this order:

  1. Read-only kill switch — BAQYLAU_DASHBOARD_READONLY=1 makes every POST a 403 "control plane disabled (read-only)" (remote eyes, no remote hands).
  2. Content type — must be application/json, else 415.
  3. Origin allowlist — a present Origin not in ALLOWED_ORIGINS → 403 "cross-origin". The allowlist is http://127.0.0.1:8377, http://localhost:8377, the public URL (BAQYLAU_DASHBOARD_PUBLIC_URL, default https://baqylau.zhambyl.top), plus BAQYLAU_DASHBOARD_ORIGINS extras.
  4. Caller proof — EITHER the custom header X-Baqylau: 1 (a cross-origin simple POST can't set it; a fetch that tries triggers a preflight this no-CORS server never answers) OR a present-and-allowlisted Origin (kept for sendBeacon-style senders that cannot set custom headers). Neither → 403.
  5. Size cap — Content-Length over the cap → 413. Caps: POST_MAX = 64 KiB default, UPLOAD_MAX = 14 MiB (uploads), HOOK_MAX = 4 MiB (hook deliveries).
  6. JSON parse (guard variant only) — non-JSON or non-object body → 400 "invalid JSON".

Rejections close the connection (an unread body would desync keep-alive) and are audited as web-reject state_files rows — the one place a control-plane POST could otherwise vanish without a trace. There is no CORS support at all: the server never answers preflights; same-origin is the only sanctioned browser caller.

Static files

  • Whitelist only (config.STATIC) — no user-path resolution ever. The 14 SPA parts (app.NN-name.js) are admitted by shape (^app\.[0-9]{2}-[a-z-]+\.js$).
  • index.html is rewritten on every serve: all sub-resource URLs (SPA parts, style.css, icons, manifest) get ?v=<BOOT_ID> stamped (BOOT_ID = server start ms). A fetch under the current stamp is cached hard (public, max-age=31536000, immutable); everything else is no-store. This is the cache-busting scheme that fixed both the stale-JS-on-mobile bug and the tunnel refresh burst.
  • /sw.js and /favicon.ico are served at the root (service-worker scope; favicon auto-discovery) via their own routes.

Error handling

Both do_GET and do_POST wrap routing in a catch-all: client disconnects pass silently; anything else is audited (dashboard request / dashboard POST errors rows) and answered 500 {"error":"internal"}. Inside the canonical router, KeyError/TypeError/ValueError from validation become 400 {"error": <message>}. Unknown paths are 404 {"error":"not found"}. Malformed application input goes through _reject_input, which audits before rejecting.

3. Every client of the layer

All non-browser clients go through app/daemon_client.py (get_text, post_json, post_bytes, sse_events, pane_frames, run_pane), which owns the base URL and stamps X-Baqylau: 1 on every POST. There is deliberately no fallback to a direct store read — the daemon is the one interpreter; a client that cannot reach it says so (DaemonUnreachable).

4. Endpoint reference — all requests and responses

Conventions: * marks a required field. All JSON POST endpoints sit behind the POST guard and share its 403/413/415/400 rejections; those are not repeated per endpoint. All type names link to the wire-type appendix. Validation failures in the canonical router are 400 {"error": <message>}.

4.3 Streams (SSE)

All streams: 200 text/event-stream, held open forever, 0.25 s poll loop, comment heartbeat (: beat) after 15 s of silence. The connection ends only when the client goes away.

SSE/api/stream — the global stream

consumer: SPA shell (session list, usage, notifications)
event: ready         data: {"boot_id": "<ms-timestamp>"}     — first frame, always;
                     a reconnecting page that sees a NEW boot_id knows the server
                     restarted and its loaded JS may be stale
event: application   data: <GlobalApplicationSnapshot>        — sent only when the
                     sorted-compact serialization differs from the previous frame
: beat                                                        — idle heartbeat

No id: on any frame — reconnect replays nothing; the snapshot is total, so nothing is lost.

SSE/api/sessions/<session_id>/stream — the one-cursor session stream

consumer: SPA session page · query: after_cursor, actor_id · header: Last-Event-ID (wins over after_cursor)
id: <cursor>
event: activity      data: {"cursor": int, "items": [DashboardItem…],
                            "snapshot": <DashboardSessionSnapshot>}
event: application   data: <SessionApplicationSnapshot>       — change-detected, no id:
: beat

activity frames carry the canonical cursor as the SSE id, so the browser's native Last-Event-ID reconnect resumes exactly where it stopped. Items are re-presented only for activities whose source events actually changed. The activity payload is the one place encoded with ensure_ascii=False compact separators.

SSE/api/sessions/<session_id>/panes/<mirror|scoreboard>/stream

consumers: the two kitty pane processes · query: width* (> 0 — the client terminal's columns)
event: session   data: {"session_id": str}    — sent once the session's row exists
                 (the stream waits, beating, for a pane that connected before the
                 session's first fact committed — this route is matched BEFORE the
                 generic session resources for exactly this reason)
event: frame     data: {"ansi": str}          — a full repaint rendered server-side
                 at the client's width from the shared width-independent block model
event: error     data: {"error": "pane stream failed"}   — after an audited failure
: beat                                        — the client's resize/liveness clock

Unknown pane kind → 404; bad width → 400. Each connection is an audited streams row (pane-mirror/pane-scoreboard, ended client-gone/error). A resize is a reconnect at the new width; the client treats a 10 s read stall as a dead daemon and reconnects.

4.4 Evidence plane

POST/api/harnesses/<harness>/hooks

consumers: the two hook clients · guard: bytes variant, cap HOOK_MAX = 4 MiB

Request body: the hook's exact stdin bytes. Not parsed here, not a JSON envelope (though the guard still requires Content-Type: application/json, which the harness's stdin is). What the hook process observed around itself rides four flat headers:

X-Baqylau-Terminal-Window: <kitty window id>        (optional)
X-Baqylau-Harness-Process: <CLI pid in the hook's ancestry>   (optional, int)
X-Baqylau-Account-Id:      <shell-selected account> (optional)
X-Baqylau-Account-Name:    <its display name>       (optional)

These become a HarnessHookRequest(payload, terminal_window_id, harness_process_id, account_id, account_display_name) handed to the plugin's HarnessHookGateway, which parses, produces raw events, and returns the synchronous reply. Recording happens on this HTTP thread — the interpreter translates later.

Response 200: the gateway's raw reply bytes, verbatim (possibly empty) — the hook prints them to its harness; this is how a hook decision (e.g. a Claude Code hook JSON reply) rides the HTTP response. Errors — all audited server-side, because the hook client swallows everything: 404 {"error"} unknown harness / harness accepts no hooks; 400 {"error"} gateway parse failure; 409 {"error"} RawEventRecorderError (evidence corruption — same raw_event_id, different bytes).

4.7 Files & dictation (the _PostMixin fallback routes)

POST/api/application/uploads — stage a composer attachment

consumer: SPA composer · guard cap raised to UPLOAD_MAX = 14 MiB (base64-inflated 10 MB image + envelope)

Request: {"session_id"?: str, "name"*: str, "mime"?: str, "data"*: base64-str}. Transport is JSON+base64, not multipart, deliberately: it keeps the whole POST-guard defense with no boundary parser. The name is reduced to a sanitized basename; bytes land under the app data dir in a per-session subdir (pruned after 7 days at boot).

Responses: 200 {"ok": true, "path": abs-str, "name": str, "mime": str, "is_image": bool} — the composer injects path as an @path mention; 400 bad fields / bad base64 / empty; 413 too large; 500 write failure. Every attempt is a web-upload audit row.

POST/api/application/clipboard-files — resolve pasted file promises

consumer: SPA composer

Request: {"names"*: [basename…], "session_id"?: str}. The server shares the macOS pasteboard with kitty and returns full paths only for exactly-matching basenames — a remote device can never be handed an unrelated host path. Response 200 {"paths": [abs-str…]}; a miss is paths: [], not an error. Audited as web-clipboard.

POST/api/application/dictation-token — mint a Deepgram grant

consumer: SPA composer/dialogs (mic button)

Request: {"sample_rate"*: int (bounded), "harness"*: str, "working_directory"?: existing-dir-str}. The stdlib server can't speak WebSocket and must never see audio; its whole role is trading the on-disk API key for a ~30 s single-purpose JWT plus the fully-assembled listen URL.

Responses: 200 {"token": str, "expires_in": int?, "ws_url": str}; 400 bad rate / missing harness / bad directory; 501 no key configured; 502 grant failed. Every attempt is a web-dictate audit row; the API key never appears in any response or audit row.

6. Serialization rules and their sharp edges

to_wire is 10 lines of generic reflection — and every quirk of it is now wire contract:

  • Dataclass → dict of every declared field, exact Python names, declaration order. None is always emitted as null, never dropped. ClassVars (the controls' control_name) are invisible.
  • Mapping → dict with str()-coerced keys; tuple → array. list is NOT recursed — a list-typed field would ship its elements raw. Nothing uses lists today (tuples everywhere); it is a live trap.
  • Decimal → string. UsageSummary.cost_in_usd, UsageWindow.used_percent and UsageRow.scheduling_score arrive as JSON strings — while InsightWindow.cost_in_usd is a float number. The same concept crosses the wire as two different JSON types depending on endpoint.
  • Two encoders. Normal responses: json.dumps(obj, default=str) — ASCII-escaped, unsorted keys, and a default=str safety net that silently stringifies anything unexpected instead of failing. SSE activity frames alone: ensure_ascii=False, compact separators.
  • No schema exists anywhere. The union of what the SPA reads is the de-facto contract; nothing machine-checks that the 23 DashboardItem keys or the ControlOutcome variants stay in sync with the JS.
  • Validation is all hand-rolled: ~30 repetitions of the isinstance-check-then-ValueError pattern (_required_text, _optional_integer, _scalar_values, _attachments, inline checks). Some responses bypass to_wire entirely and are hand-built dicts (/api/harnesses, /api/terminal/panes, all the {"saved": true} family) — three different ways of producing JSON in one module.

9. Refactoring proposal

The three problems, restated precisely

  1. Too much custom HTTP. ~1,600 lines of hand-rolled routing, guard, gzip, SSE framing, cache stamping and validation — all of which a framework provides, tested, with better ergonomics.
  2. Nothing is typed on the wire. Requests are hand-validated dicts (30+ repetitions of the isinstance dance); responses are a mix of reflective to_wire, hand-built dicts, and fixed literals; no schema exists, so client/server drift is caught only by the golden HTTP tests or in production.
  3. Wrong home. dashboard/http/ serves the dashboard, the hooks (evidence plane!), both terminal panes, the keybinding handler and two click handlers. The evidence plane's one write endpoint living inside a presenter package inverts the architecture's own layering story.

Proposal 1 — a new top-level package: api/

Extract the HTTP layer into its own layer, sitting where it truthfully sits — above app/, beside the presenters, owned by neither:

api/
  server.py          # serve(): lock, audit stream, uvicorn, the three threads — the ONE
                     #   graph-builder (takes dashboard/http/handler.py's place in the
                     #   architecture test's allowlist)
  guard.py           # the POST-guard as FastAPI dependencies: readonly, origin allowlist,
                     #   X-Baqylau header, per-route body caps
  models/            # every request/response model (see Proposal 2)
    control.py  application.py  evidence.py  streams.py  wire.py
  routes/
    evidence.py      # POST /api/harnesses/{harness}/hooks         — raw bytes in/out
    sessions.py      # /api/sessions*, controls, activity
    streams.py       # the three SSE endpoints
    panes.py         # /api/terminal/panes, /api/terminal/views
    application.py   # preferences, drafts, presence, telemetry
    files.py         # uploads, clipboard-files, dictation-token
    static.py        # index stamping, whitelist, sw.js, favicon
  http_config.py     # PORT/HOST/caps/headers/origins — moved OUT of dashboard.config
  • dashboard/ keeps what is genuinely dashboard: the SPA assets, presenters, markdown/diff/ansi rendering, notify. api/ imports application services (app/) and presenters (dashboard/), never the reverse.
  • app/daemon_client.py stops importing dashboard.config (a terminal-side client importing the web-presenter package today) and reads api/http_config.py — or better, the shared constants move to core/ so clients import no server code at all.
  • Layering table addition: api/ may import domain/contracts/runtime/app/core + presenters; still no harness vocabulary (the {harness} path segment stays a string resolved through the registry, exactly as today).
  • Update the architecture test's allowlist (build_default_application: app/bootstrap.py + api/server.py) in the same commit — and CLAUDE.md/docs, which this page shows are already drifting.

Proposal 2 — FastAPI + Pydantic, typed end to end

Framework: FastAPI on uvicorn. This is the repo's first third-party runtime dependency — worth stating plainly, because today the whole system is stdlib-only. What it buys: declarative routing (the URL space readable in one place instead of an MRO), Pydantic validation replacing every hand-rolled check, OpenAPI/JSON-schema for free, native SSE via StreamingResponse, dependency injection replacing self.server.canonical_application, and a real test client. What must be preserved and how:

_post_guard (readonly / content-type / origin / header / cap)one Depends(control_plane_guard) on every mutating route; per-route body caps as parameters (POST_MAX/UPLOAD_MAX/HOOK_MAX). Keep the web-reject audit row in the dependency — it is load-bearing forensics. Do not add CORSMiddleware: never answering preflights is part of the defense.
hand routing over path segmentsAPIRouter per plane; typed path params (session_id: SessionId via a validated str subtype)

Mirror the dataclasses one-for-one initially; pin wire compatibility with golden tests (same field names, nulls present, Decimal→str via a field serializer). Retire default=str — an unserializable value should fail loudly.

Typing both sides. With Pydantic models in place, generate the OpenAPI schema at build time and derive a typed TypeScript client for the SPA (e.g. openapi-typescript) — then client/server drift becomes a compile error, closing the loop that to_wire's reflection left open. The terminal-side daemon_client can import the same request/response models directly, since client and server share the repo.

Migration plan — four reviewable steps, wire-compatible throughout

  1. Move, don't change. git mv dashboard/http api/http, split the HTTP knobs out of dashboard.config, update the two architecture-test allowlists. Pure relocation; make test green.
  2. Pin the wire. Add golden contract tests: for each endpoint, a recorded request → the exact JSON (or SSE frame sequence) expected, captured from the current implementation. test_canonical_http.py is most of this already — extend it to cover every literal response and error shape in §4.
  3. Swap the engine. Introduce FastAPI models + routers behind the golden tests, one plane at a time (application-state routes first — trivial shapes; then read API; then controls; SSE and hooks last, they're the load-bearing ones). Restart discipline is unchanged: stop/start the daemon, hard-reload the browser.
  4. Reap. Delete _Base/_GetMixin/_PostMixin/_CanonicalMixin and the hand validators; generate the TS client; fix the deliberate wire changes only now, as their own commits (unknown session → real 404; one JSON type for cost; documented 422 validation errors). Update docs/ + CLAUDE.md + the audit-debug skill in the same commits.

Risks worth naming

  • Dependency footprint: fastapi + starlette + pydantic + uvicorn ends the stdlib-only property. If that is unacceptable, the fallback that still fixes problems 2 and 3 is: keep the stdlib server, extract api/, and hand-write the Pydantic-style models over it — but you keep maintaining the plumbing forever.
  • Async vs the graph: the application services are synchronous and SQLite-backed. Run route handlers as sync (def, thread-pool) initially — semantics identical to today's threading — and move only the SSE generators to async. Do not make the interpreter async.
  • Hook latency: hooks time out at 2 s client-side and their reply gates the harness. Benchmark the hook route before/after; recording must stay on the request path (never behind the interpreter tick).
  • Pydantic strictness: default coercion is looser than today's hand checks in places (e.g. "1" → int). Use strict types where today rejects, or the golden tests will pass while behaviour loosens.
